# Заголовок
Retry/timeout/fallback в API gateway

## Контекст
Для BR.6 нужно предсказуемое поведение при сбоях основного маршрута.

## Что нужно сделать
- Добавить timeout для вызовов провайдера.
- Добавить ограниченный retry при транзиентных ошибках.
- Добавить fallback на резервный маршрут по заранее заданному правилу.
- Вернуть понятный отказ при отсутствии доступного маршрута.

## Связанный сервис / модуль
`api-gateway`.

## Зависимости
- `07-01-provider-catalog.md`, `00-02-system-contracts.md`.

## Приоритет
P0

## MVP
да

## Критерии готовности
- При ошибке primary применяются timeout/retry по правилам.
- При наличии fallback запрос уходит на резерв.
- При отсутствии fallback клиент получает понятную ошибку.
