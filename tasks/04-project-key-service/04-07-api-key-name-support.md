# Заголовок
API key name support в project-key-service

## Контекст
Новый UI API Keys требует человекочитаемое имя ключа в таблице и модалке создания. Сейчас backend не хранит `name` для ключа.

## Что нужно сделать
- Добавить поле `name` в `api_keys` и миграцию/backfill для существующих строк.
- Расширить `POST /projects/{id}/keys`:
  - принимать опциональное `name`,
  - при пустом значении назначать безопасный дефолт.
- Расширить `GET /projects/{id}/keys` возвратом `name` для каждого ключа.
- Сохранить обратную совместимость:
  - revoke/resolve без изменений,
  - существующие клиенты без `name` продолжают работать.

## Связанный сервис / модуль
`project-key-service`, `db/init.sql`, `db/migrations`

## Критерии готовности
- Ключ можно создавать с именем и без имени.
- Список ключей стабильно возвращает поле `name`.
- Старые сценарии revoke/resolve не сломаны.
