# Заголовок
Настройки fallback-модели на уровне проекта

## Контекст
Сейчас fallback выбирается глобально по модели из `routing_rules`, из-за чего нельзя задавать отдельное fallback-правило для конкретного проекта.

## Что нужно сделать
- Добавить хранение fallback-настройки на уровне проекта.
- Реализовать API:
  - `GET /projects/{id}/routing`
  - `PUT /projects/{id}/routing`
- Для `PUT` оставить доступ только для `Admin` и `PM`.
- Проверять принадлежность проекта к `org_id` пользователя.
- Проверять, что `fallback_model_id` существует в `provider_models`.
- Писать аудит `project.routing.updated`.

## Связанный сервис / модуль
`project-key-service`, `db/init.sql`, `db/migrations`.

## Зависимости
- `00-02-system-contracts.md`
- `04-01-projects-crud.md`

## Приоритет
P0

## MVP
да

## Критерии готовности
- Для проекта можно прочитать и сохранить `fallback_model_id`.
- `Admin` и `PM` могут обновлять routing-настройку, остальные роли получают `403`.
- Настройка не выходит за границы организации.
- В аудите фиксируется `project.routing.updated`.
