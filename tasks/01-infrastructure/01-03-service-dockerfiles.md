# Заголовок
Dockerfile для каждого backend-сервиса

## Контекст
Каждый Go-сервис должен контейнеризоваться отдельно для локального оркестрирования в compose.

## Что нужно сделать
- Добавить отдельный `Dockerfile` в директорию каждого backend-сервиса.
- Использовать multi-stage сборку с компактным runtime образом.
- Проверить совместимость Dockerfile с `docker-compose.yml`.

## Связанный сервис / модуль
Infrastructure / containerization.

## Критерии готовности
- Все backend-сервисы успешно собираются в контейнеры.
- Образы стартуют и отвечают на health endpoint.
- Dockerfile не содержат лишних runtime зависимостей.
