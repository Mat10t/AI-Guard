# Заголовок
Soft-delete участника организации с защитами Admin

## Контекст
В MVP нужно рабочее управление составом организации: участника можно удалить без физического удаления данных, с сохранением аудита и предотвращением потери администраторского доступа.

## Что нужно сделать
- Добавить endpoint `DELETE /org/members/{id}` с доступом только для роли `Admin`.
- Реализовать soft-delete пользователя (`users.deleted_at = NOW()`) и отзыв всех refresh-сессий пользователя (`sessions.revoked_at = NOW()`).
- Добавить проверки: нельзя удалить себя; нельзя удалить последнего `Admin` в организации; удаление только в пределах текущей организации.
- Зафиксировать событие аудита `member.deleted`.
- Привести auth-потоки к active-only логике: login/refresh/members/update-role учитывают `users.deleted_at IS NULL`.
- Обновить схему: добавить `users.deleted_at`, обеспечить повторное приглашение того же email через partial unique index для активных пользователей.

## Критерии готовности
- `DELETE /org/members/{id}` удаляет участника soft-delete способом и возвращает `200`.
- Попытка удалить себя возвращает `400`, попытка удалить последнего Admin возвращает `409`.
- Удаленный пользователь не может пройти login/refresh.
- Повторное приглашение удаленного email успешно создается.
- В аудите появляется действие `member.deleted`.
