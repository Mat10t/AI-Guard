# Заголовок
Auth-first session layer, client guard и app shell

## Контекст
Текущий frontend работает с API, но не имеет единого session-layer и защищенной навигации после входа.

## Что нужно сделать
- Добавить единый клиентский session-layer (token + claims + refresh + logout).
- Добавить client guard для защищенных страниц (`/projects`, `/analytics`).
- Добавить общий app shell с верхней навигацией для авторизованного режима.
- Обеспечить корректное поведение при `401` (refresh, затем logout/redirect при неуспехе).

## Связанный сервис / модуль
`frontend` (Next.js app router).

## Критерии готовности
- Неавторизованный пользователь не может использовать защищенные страницы.
- Авторизованный пользователь видит верхнюю навигацию и может переходить по разделам.
- При истекшем access token выполняется refresh path без ручных действий пользователя.
